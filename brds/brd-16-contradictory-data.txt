8. Additional Notes
This BRD is the NEGATIVE TEST - CONTRADICTORY DATA scenario. It
deliberately sets inconsistent values across geography, customer,
and transaction dimensions to verify the system's behaviour:

CONTRADICTIONS INTENTIONALLY PLANTED:

 1. Domestic or Cross-Border = Domestic
    AND Beneficiary Country = Iran
    (Iran is by definition cross-border AND sanctioned)

 2. High Risk Jurisdiction Flag = No
    AND Beneficiary Country = Iran
    (Iran is on FATF high-risk list)

 3. PEP Exposure = No
    AND Sanctions Exposure = Yes
    (Sanctions-relevant customers must trigger PEP/HRCE review)

 4. Vendor section = Not Applicable
    AND Sanctions Exposure = Yes
    (Sanctions screening requires a screening vendor)

 5. Cross Border Processing = No
    AND Beneficiary Country = Iran
    (Iran = cross-border)

EXPECTED SYSTEM BEHAVIOUR:
 (a) BRD extraction should populate fields with low confidence and
     emit a provenance_notes.low_confidence_fields warning covering
     the contradicting fields.

 (b) Intake completeness should NOT silently fill the contradicting
     booleans with defaults. The user must resolve each contradiction.

 (c) Risk calculation should be allowed to run if the user explicitly
     confirms the data. In that case:
     - Sanctions Exposure = Yes fires Risk-Floor Rule #4
     - Geography contradiction forces inherent geography score >= 95
     - Residual rating is forced to CRITICAL (floor = 65)
     - The AI assessment MUST explicitly call out the contradictions

 (d) The system should NOT silently treat Iran as "domestic." It
     should either reject the contradictory record or override the
     Domestic flag to Cross-Border automatically.

 (e) Analyst review and Committee decision should both refuse to
     close the request below CRITICAL until contradictions are
     resolved.

This BRD tests defensive coding, cross-field validation, and the
sanity-check layer above the risk engine.
